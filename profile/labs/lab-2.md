# Лабораторная 2

## Отрабатываемый материал

Основные концепции ООП, GRASP, SOLID, структурные паттерны.

## Глоссарий

- Тара – пластиковый контейнер, в котором лежат экземпляры
- Палета – деревянный поддон, на котором размещены тары
- Репозиторий – класс/объект, ответственный за хранение каких-либо сущностей
- ОВХ - объёмно-весовые характеристики

## Введение

Экземпляры товаров на складах хранятся в различных контейнерах, имеющих вложенность.
Для оптимального хранения необходимо сформировать определённые правила, по которым экземпляры распределяются по различным контейнерам.

При размещении экземпляра на складе необходимо поместить его в какую-либо тару, которая, в свою очередь, находится на определённой палете.
Палеты в дальнейшем используются для хранения и перемещения тар по складу.

Логика хранения экземпляров подразумевает различные ограничения: по ОВХ, по категориям, по срокам годности.

Для обеспечения выполнения данных правил необходимо реализовать систему, выбирающую целевую тару по ряду определённых бизнес-правил.

## Задание

Спроектируйте и реализуйте объектную модель, описывающую правила распределения экземпляров по тарам.

## Предметная область

### Sku

- Идентификатор
- Категория (электроника, выпечка, ФРОВ) (см. примечание 1)
- ОВХ

### Экземпляр

- Идентификатор
- Sku
- Срок годности (опциональный)

### Товарная группа

Какое-либо объединение sku

- Sku может иметь до 1 товарной группы
- Содержит набор категорий

### Правило товарного соседства

Некоторые экземпляры запрещено хранить в одной таре (например, спички и бензин). Проверки допустимости хранения экземпляров в одной таре называются проверками товарного соседства.

- Для проверок товарного соседства используются товарные группы
- Если экземпляр принадлежит какой-либо товарной группе, он может быть помещён только в тару с экземплярами, принадлежащими той же товарной группе
- Если экземпляр не принадлежит ни одной товарной группе, он может быть помещён только в тару с экземплярами, также не принадлежащими ни одной товарной группе

### Сервис тар

Сервис, ответственный за операцию добавления экземпляра в тару

- Использует репозиторий для получения/сохранения данных об экземплярах в тарах
- При добавлении экземпляра в тару
    - Получает уже находящиеся в таре экземпляры
    - Проверяет допустимость добавления экземпляра по правилу товарного соседства
    - Проверяет допустимость добавления экземпляра по максимальному ОВХ тары
- Добавление может завершиться неуспешно

### Правила распределения экземпляров

Логика распределения экземпляров представляется деревом правил.

#### Для тар

Самое простое правило. Выполняет попытку добавления экземпляра в тару в соответствии с логикой, описанной в сервисе тар.

#### Для палет

Выполняет попытку добавления экземпляра во вложенные в палету тары до первого успеха в соответствии с правилами тар.

#### Маршрутизатор категорий

Правило распределения экземпляров по другим правилам относительно категории экземпляра.

- Содержит маппинг категория-правило
- Содержит правило по умолчанию (используется, если для категории экземпляра не нашлось правила)

#### Дополнительные правила
Необходимо иметь возможность добавить к правилу логику, связанную со сроком годности.
Экземпляр можно поместить
- только если у него не истёк срок годности или его нет
- только если он просрочен

Необходимо иметь возможность логировать информацию о результате выполнения правила.

---
## Примечания
1) Есть множество категорий, у каждой есть идентификатор.

Валидация корректной вложенности правил находится за пределами домена лабораторной работы и не требуется

---

## Нефункциональные требования
- Реализация логирования должна быть тестируемой. Например, проверить вывод на консоль при вызове некоторых поведений в тестах - невозможно. Нужно иметь возможность реализовать в тестах mock-тип, который будет вести счётчик вызовов
- При тестировании логики сроков годности будет необходимо манипулировать системным временем. Получение текущего времени должно быть скрыто за абстракцией

## Test cases

1) Тара с экземпляром категории «бумага», товарное соседство настроено так, что категории «бумага», «ножницы» и «камни» не пересекаются. Экземпляр категории «ножницы» не добавляется в тару.
2) Тара с максимальным ОВХ, равным ОВХ уже находящегося в ней экземпляра. Добавление второго экземпляра, превышающего оставшийся ОВХ, завершается неуспешно.
3) Маршрутизатор категорий без маппинга и с правилом по умолчанию - добавление в тару. Экземпляр категории «выпечка» помещается в тару.
4) Маршрутизатор категорий с маппингом: категория «электроника» - правило для тары А, категория «ФРОВ» - правило для тары Б. Экземпляры категорий «электроника» и «ФРОВ» добавляются каждый в свою тару в соответствии с маппингом.
5) Экземпляр без товарной группы добавляется в тару, где уже есть экземпляр с товарной группой. Добавление завершается неуспешно.
6) Логирующее правило вызывается для успешного и неуспешного добавления экземпляра. Логгер фиксирует оба результата.
7) Палета с двумя тарами: одна для просроченных экземпляров, вторая для экземпляров с не истёкшим сроком годности. Просроченный экземпляр добавляется в тару с просрочкой.
